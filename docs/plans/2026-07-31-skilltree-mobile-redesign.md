## 1. 行业参考

为定位移动端技能树的合理范式，我们横向对比 4 款在移动平台被广泛验证的成熟方案：

- **《原神》/《崩坏：星穹铁道》天赋树**：竖向滚动长图，分支以列呈现；点击节点即从底部弹出详情面板，展示名称、类型、描述与解锁消耗，桌面端另保留 hover tooltip。
- **《暗黑破坏神：不朽》Paragon 系统**：竖向面板 + 多分支并列，分支间用分页签切换，单屏聚焦一条成长线，避免整树一次性铺开。
- **《最终幻想 XIV》技能树（移动端适配）**：竖向树状结构，节点点击后弹出详情面板，强调"先聚焦、后展开"的二级信息层级。
- **《绝区零》/《崩坏 3》角色技能页**：技能以竖向列表排列，配合顶部分页签（按角色/技能类型切分），每屏只承载一个子集。

### 提炼：移动端通用最佳实践（6 条）

1. **竖向优先滚动**：深度方向天然映射为纵向滚动，符合拇指操作习惯，规避横向超宽画布。
2. **分支用分页签 / 分段控件承载**：5 条分支各自独立成屏，消除跨分支横向 fan-out。
3. **点击 → 底部抽屉（bottom-sheet）**：节点详情从底部滑出，含名称/类型/描述/消耗/解锁按钮，替代原地 expand 或 tooltip。
4. **≥44px 触摸热区**：每个可点击节点命中区不小于 44×44px，保证手指精准点选。
5. **点击聚焦居中 + 适度放大**：选中节点平移至视口中心并轻微放大，降低寻路成本。
6. **最小缩放保证可读**：设置缩放下限（建议 ≥ 0.6），禁止为容纳整树而压到不可读。

## 2. 推荐交互模型（移动端）

### 2.1 分支导航
- **推荐方案**：顶部**分段控件（Segmented Control）**切换 5 个分支（war / bly / nfr / eco / utl），每屏只渲染一个分支的竖向链。
- **备选方案**：左右滑动列（swipe columns），五条分支作为可横滑的页面。
- **推荐理由**：分段控件单屏聚焦、标签可见、误触率低；滑动列虽沉浸，但分支入口不如标签直观，且与现有 `bindSkillTreePan` 的横向 pan 手势存在冲突风险。

### 2.2 节点详情
- **推荐**：点击节点 → **底部 bottom-sheet 抽屉**，含名称 / 类型 / 描述 / 消耗 / 解锁按钮；桌面端保留 hover tooltip 不变。
- **备选**：原地 expand / tooltip。
- **理由**：bottom-sheet 信息密度高、不遮挡其他节点、单手可达；原地 expand 在密集竖向链中会推挤相邻节点造成错位。

### 2.3 聚焦、缩放与手势共存
- **点击聚焦居中 + 适度放大**：推荐开启——选中节点平移至视口中心并放大至可读性阈值（与 `fitSkillTreeView` 的 `stScale` 下限解耦，详情态单独放大）。
- **触摸热区**：节点命中区 ≥44px，复用 `.touch-device .st-world .altar-card` 已有的 58px 纯图标模式。
- **与现有捏合平移共存**：`bindSkillTreePan`（1147–1221）的 pinch / pan / wheel 在单分支竖向视图内继续生效，`--st-zoom` 字号自适应保留。
- **"解锁保持视图"**：推荐保留——解锁后不改变当前滚动位置，避免玩家丢失上下文。

## 3. 二叉树布局重构建议（核心）

### 3.1 宽幅 fan-out 根源
当前 `renderSkillTree()`（`src/ui.js:963–1115`）把**兄弟关系映射到横向**（`x = bandX + yPos*COL_W`），把**深度映射到纵向**（`y = TITLE_OFF + depth*ROW_H`），再靠 `bandX += (maxSlot+1)*COL_W + BAND_GAP` 把 5 个 band 横向累加。结果：深度越大单 band 越宽，5 band 横向拼贴 → world 极宽；手机整树 fit 后 `stScale` 触底 0.2，不可读（见 `fitSkillTreeView` 1121–1134）。

### 3.2 移动端主轴对调
建议**坐标轴对调**：`depth → y`（向下滚动），`兄弟 → x`（有限横向偏移）。每个分支改为**竖向链**：从上到下滚动，二叉分叉在链内最多展开 2 条并行竖线，总宽度被钳制在单屏内。竖向链宽度只取决于同深度并行分叉数（≤2），与总深度无关，彻底消除横向 fan-out。

### 3.3 是否调整 `data.js` 的 `prereq`
- **不改 prereq（推荐）**：图标与节点数零变动，仅改渲染坐标映射；`validate_skilltree.mjs` 的 ≤2 子约束天然满足（已二叉化），风险最低、存档完全兼容。
- **改 prereq（不推荐，除非必要）**：若某分支竖向链过长需重排，可微调 prereq 顺序，但必须保证二叉树校验仍 ≤2 子、零新增节点。用户已允许改分叉结构，但图标不变、节点数尽量不变——故优先不改。

### 3.4 双亲汇聚 keystone 的正确渲染
`war_keystone_omni` 等 keystone 的 prereq 为 `['war_dmg','war_axe_extra']`，属**双亲汇聚**点。竖向布局下：两条上游竖线在 keystone 处**汇合到同一 y 行**，用"合流节点"视觉（双入边箭头）表达；渲染时以 keystone 的 `max(prereq.depth)+1` 作为自身 depth，避免与两条父链错位。桌面端同理。

### 3.5 桌面端处理
建议**桌面不同步退化**：保留 5 分支总览（或也改为竖向多列并排），利用大屏横向空间展示全树；仅移动端收敛为单分支竖向链 + 分段控件。避免"为移动改、连桌面一起砍"的退化。

## 4. 关键决策点清单（需用户拍板）

1. **分支导航形态**：分段控件 / 分页签（推荐）vs 左右滑动列。→ 推荐：顶部分段控件切换 5 分支，每屏一个。
2. **节点详情形态**：底部 bottom-sheet（推荐）vs 原地 expand / tooltip。→ 推荐：bottom-sheet 抽屉。
3. **桌面是否同步改**：保留 5 分支总览（推荐）vs 也改竖向多列 vs 完全不改。→ 推荐：保留总览，仅移动端收敛。

## 5. 风险与缓解

在"图标不变、节点数尽量不变"前提下，布局 / 分叉改动的回归风险与缓解：

- **≤2 子约束**：任何 prereq 调整都须经 `validate_skilltree.mjs` 校验并设 CI 卡点；不改 prereq 时该约束天然满足。
- **prereq 可达性**：竖向链渲染后需验证所有 keystone 的双亲链均可见可达，新增合流节点不得产生悬空边。
- **洗点 / 重置**：底部抽屉的解锁 / 重置按钮必须复用现有洗点逻辑，避免解锁态与存档不一致。
- **存档兼容**：节点 id 与图标不变，仅坐标映射变化，存档（已解锁集合）向后兼容；建议加一次迁移校验，防止旧档深度字段错位。
- **手势共存回归**：`bindSkillTreePan` 与分段控件、bottom-sheet 的触摸事件需做命中优先级测试，防止 pan 吞掉点击。
