## 2. entities.js 改动（Player 属性机制层）

### 2.1 `Player.reset()` 新增 8 个字段（7 属性 + lastHitTime，追加在 `this.lifesteal = 0;` 之后）

```js
// ===== S 档新属性（2026-07-26）=====
this.critChance = CRIT_CHANCE_BASE;  // 暴击率（0~1，硬上限 CRIT_CHANCE_CAP）
this.critMul = CRIT_MUL_BASE;        // 暴击伤害倍率（≥1）
this.maxShield = 0;                  // 护盾上限（0=无护盾流派）
this.shield = 0;                     // 当前护盾
this.shieldRegen = 0;                // 护盾恢复速度（盾/秒）
this.armor = 0;                      // 防御（固定减伤值）
this.dodgeChance = 0;                // 闪避率（0~1，硬上限 DODGE_CAP，基础 0）
this.lastHitTime = -999;             // 最后一次实际承伤的游戏时间（受击打断回盾用）
```

`entities.js` 顶部 import 需追加：`CRIT_CHANCE_BASE, CRIT_MUL_BASE, CRIT_CHANCE_CAP, DODGE_CAP, SHIELD_REGEN_DELAY, DAMAGE_MIN`（自 data.js）。

**注意**：`lastHitTime` 用游戏时间（`this.game.time`）而非时间戳；初始 `-999` 保证开局即视为「久未受击」、可立即回盾（若 `maxShield>0`）。

### 2.2 新增 `Player.rollCrit(baseDamage)`（新方法，供所有伤害结算点调用）

```js
// 暴击结算：返回 { damage, isCrit }。所有「对敌伤害」必须先经此函数（含 DOT 每 tick）。
rollCrit(baseDamage) {
  const isCrit = Math.random() < this.critChance;
  return { damage: isCrit ? baseDamage * this.critMul : baseDamage, isCrit };
}
```

**规则**：DOT（reaper 的 rend）每 tick 独立 roll；AoE 每次命中独立 roll（不设「一次施法共享一次 roll」）。S 档唯一结算口径。

### 2.3 `takeDamage(amount)` 重写（承伤四段，顺序固定）

现有实现整体替换为：

```js
// 返回 true=实际承受了伤害；false=未承伤（iframes 中 或 闪避成功）。
takeDamage(amount) {
  if (this.iframes > 0) return false;
  // ① 闪避：概率完全免伤，但仍刷新 iframes 保持受击节奏
  if (Math.random() < this.dodgeChance) {
    this.iframes = 0.5;
    this.game?.fx?.spawnDamageNumber(this.x, this.y - 18, '闪避!', '#9fd8ff');
    return false;
  }
  // ② 防御：固定减伤后乘百分比乘区，保底 DAMAGE_MIN
  let dmg = Math.max(DAMAGE_MIN, (amount - this.armor)) * (this.damageTakenMul || 1);
  // ③ 护盾吸收：先扣盾，扣完再扣血
  if (this.shield > 0) {
    const absorbed = Math.min(this.shield, dmg);
    this.shield -= absorbed;
    dmg -= absorbed;
  }
  // ④ 扣血 + 受击打断回盾计时
  this.hp -= dmg;
  this.lastHitTime = this.game ? this.game.time : 0;
  this.iframes = 0.5;
  if (navigator.vibrate) navigator.vibrate(50);
  return true;
}
```

**行为契约**：
- 闪避成功也置 `iframes = 0.5`。
- 护盾被击穿的那一击：溢出部分正常扣血；`lastHitTime` 无论盾破与否都刷新（只要实际承伤，含盾吸收也算「受击」，打断回盾）。
- 35% 触碰伤害上限（`cap = player.maxHp * 0.35`）在**调用 takeDamage 之前**已截断，armor 减免发生在 cap 之后；不得把 cap 移进 takeDamage。
- `volatile` 词缀爆破伤害、`enemyProjectiles` 弹幕伤害均走同一 `takeDamage`，自动获得闪避/防御/护盾。

### 2.4 `Player.update()` 追加护盾恢复（在 regen 回血段之后）

```js
// 护盾恢复：受击打断 SHIELD_REGEN_DELAY 秒后开始回盾（封顶 maxShield），死亡后不回
if (this.maxShield > 0 && this.shieldRegen > 0 && this.hp > 0) {
  const nowT = this.game ? this.game.time : 0;
  if (nowT - this.lastHitTime >= SHIELD_REGEN_DELAY) {
    this.shield = Math.min(this.maxShield, this.shield + this.shieldRegen * dt);
  }
}
```

**与 `regenRate` 的关系**：回血走血池、回盾走盾池，互不干扰；回血不受打断限制。恢复期间护盾条 UI 由 ui.js 每帧读值刷新（见 §4.2），Player 层不推消息。

### 5.2 weapons.js 接入（暴击 roll，D2 默认值）

原则：**所有对敌伤害先经 `player.rollCrit()`，暴击飘字金色加「暴击」语义**。暴击率/暴击伤按 D2 默认值（critrate +5%/级、critdmg +15%/级、cap 0.75，见 §1.1/§1.2）。

- 提供统一辅助（放在 `WeaponSystem`）：
  ```js
  // 伤害+飘字一把梭：所有直伤点改用此函数（knockX/Y 可选）
  hitEnemy(e, baseDamage, knockX = 0, knockY = 0) {
    const { damage, isCrit } = this.game.player.rollCrit(baseDamage);
    this.game.enemies.damageEnemy(e, damage, knockX, knockY);
    this.game.fx.spawnDamageNumber(
      e.x, e.y - e.radius, Math.round(damage),
      isCrit ? '#ffd24a' : undefined,
      isCrit,                          // 第 5 参：暴击标记（放大字号）
    );
    return { damage, isCrit };
  }
  ```
- `fx.spawnDamageNumber(x, y, amount, color, isCrit=false)` 增加第 5 参（systems.js）：`isCrit` 时数字字号放大 1.35 倍、文字前缀 `暴击 `；**仍受每帧 14 个节流约束**——暴击数字与非暴击共用同一队列（R6 风险缓解）。
- **改造点清单**（weapons.js 现存 ~20 处 `damageEnemy(...)` 直伤调用，逐处替换为 `hitEnemy`）：
  - 投射物命中：`updateProjectiles` 内 `p.damage` 结算点。`p.damage` 在 fire 时已乘过 `damageMul`——**暴击 roll 在命中时进行**（每敌每次命中独立），`p.damage` 作为 `baseDamage` 传入。
  - 圣水/领域 pool tick：`updatePools`。
  - 雷霆链击：`strikeLightning` 两段（首击 + 跳跃，跳跃保持 `*0.85` 衰减后再 roll）。
  - 光环/长鞭/圣印/神器各 fire/updateArtifact 分支内的 `damageEnemy` 直调点。
  - **rend DOT**（entities.js）：每 tick 的 `e.rend.dps * dt` 结算追加独立 roll——在 tick 内 `player.rollCrit(d)`，暴击时该 tick 飘字金色。DOT 每 tick roll 是定稿口径，不得改为施加时单次 roll。
  - **不暴击的例外**：`crimson` 神器命中回血、`p.lifeSteal`/`lifesteal` 回血、`reaper` 收割回能——回复效果，不接暴击。
- 飘字颜色：允许各调用点保留原颜色作为非暴击色，仅暴击时强制 `#ffd24a`。

### 5.3 upgrade.js 接入（D3：分类权重 + 合并生效 + 保底）

- 6 新被动定义进 `PASSIVES` 后，`buildPool()` **自动**将其纳入候选（遍历 `Object.values(PASSIVES)`），无需改遍历逻辑。
- **分类权重（D3 新增）**：`rollOptions()` 按玩家已投资分类倾斜。基础权重 `W0 = 1.0`；先统计玩家已持被动的 `catCount[cat]`（`cat ∈ {offense,survival,utility}`），每个候选最终权重 `w = W0 * (1 + Δ * catCount[candidate.category])`，`Δ = 0.6`[校准]；按权重抽样三选一。走某流派时更易滚到同系被动，成型更顺、减少「看脸」。
- **保底 1 张进攻向或武器向**：`rollOptions()` 保底过滤条件改为 `o.isWeapon || o.def.category === 'offense'`（critrate/critdmg 带 `category:'offense'`），防稀释后开局三张全生存向、流派不可成型。
- **合并生效**：`swift`/`rage` 已从 `PASSIVES` 删除，自然退出候选；无需在 buildPool 额外排除。
- **不做渐进解锁**（Q5 全开放）：新被动开局即入池。
- `describe()` 无需改：新被动走现有 `passive` 分支。
