## 1. 节点详情 hover · 信息层级规范

### 1.1 设计目标
卡片本身已显示 名称 / 类型 / 描述 / 成本 / 购买按钮，但缺两样关键决策信息：**前置节点名 + 各自解锁状态**、以及**更明确的当前状态与锁因**。hover 浮层只补这两类缺口，不做卡片已有信息的简单重复。

### 1.2 字段与信息优先级（高 → 低）
> 任务建议字段为「节点名 / 类型标签 / 完整效果描述 / 灵魂成本 / 前置节点清单含各自状态 / 当前节点解锁状态」。本规范在保留全部 6 字段的前提下，**重排优先级**：将"当前状态 + 锁因"前置到 P1——因为它是玩家悬停时最决策相关的信息（"我现在能买吗？为什么能/不能？"），而非读完描述才知。

| 优先级 | 字段 | 内容 | 视觉处理 |
|---|---|---|---|
| **P0 身份** | 节点名 + 类型标签 | 卡片 h3/`.st-type` 的强化呈现 | 节点名用金 `#d4af37` 粗体；类型用 **chip**（分支色描边 + 类型形状标记：●圆=stat / ■方=modifier / ⬡六边=keystone / ◌虚线环=gate），三重编码不依赖颜色 |
| **P1 状态** | 当前节点解锁状态 + 锁因 | `owned` / `available` / `locked`，locked 时显式原因 | 状态 pill：owned=分支色「已点亮」；available=金「可解锁 ✓」；locked=灰 `#a0a0b0` + 原因文案 |
| **P2 成本** | 灵魂成本 | 数字（卡片已显示，浮层强调可负担性） | 灵魂图标 + 数字；灵魂充足=金，不足=暗红 `#8a3a3a` |
| **P3 效果** | 完整效果描述 | 卡片 `.ac-desc` 的**未截断**全文；标 ⚠️ 机制变更 | 骨白 `#e8e0d0`；机制改动（`HOOK`）加一行"机制变更"提示 |
| **P4 前置** | 前置节点清单含各自解锁状态 | 每个 prereq 一行：`[状态点] 节点名 (已解锁/未解锁)`；gate（prereq 空）显示「无前置 · 分支入口」 | 状态点：●绿灰=已解锁 / ○灰=未解锁；锁因示例："需先解锁：征伐之门、武器精通"；门槛锁："需通关 normal 难度" / "需通关 hard 难度" |

### 1.3 浮层版式（示意，非代码）
```
┌──────────────────────────────────────┐
│ [类型chip]  节点名(金)                 │  P0
│ ──────────────────────────────────── │
│ 状态：可解锁 ✓  │  灵魂：⛁ 300(金)    │  P1 + P2
│ ──────────────────────────────────── │
│ 效果：<完整未截断描述>                 │  P3
│ ──────────────────────────────────── │
│ 前置：● 征伐之门 (已解锁)              │  P4
│       ○ war_dmg  (未解锁)             │
└──────────────────────────────────────┘
```
- 面板：暗石背景 `rgba(24,18,40,.95)` + 1px 金 `#d4af37` 描边 + 圆角 6px（对齐 art-spec §2.6 详情卡视觉）。
- 定位：节点右下方；做边界检测避免溢出 `.st-branch-grid` / 视口。
- 数据驱动：浮层内容由节点数据 + 实时 `owned` 状态生成；购买重渲染后若浮层仍打开，**同步刷新** P1/P4（避免显示过期状态）。

### 1.4 移动端降级策略（二选一 · 明确结论）
**结论：采用 A —— 点击卡片展开详情面板（tap-to-expand detail panel）。理由：**

1. **信息完整性 1:1**：hover 浮层的核心新增价值是"前置链 + 各自状态 + 锁因"的多行结构化信息。方案 B（常驻精简摘要）要么把这些信息塞进全部 39 张卡片（→ 卡片拥挤、违反认知过载红线，且 art-spec §2.3 刻意保持卡片简洁：名/类型/描述/成本/按钮），要么保持截断（仍不解决"缺前置状态"的痛点）。两者都半途而废。
2. **零摩擦、单真源**：技能树是**元进度屏、非战斗内**，无操作压力；tap 展开面板可承载与桌面 hover **完全相同**的 P0–P4 结构（同一份渲染模板，不维护两套布局）。
3. **交互划分清晰**：触屏下禁用 `:hover` 浮层；卡片**本体 tap** → 展开面板；面板内**购买按钮 tap** → 购买（复用既有 `.ac-buy`）。点面板外/关闭键收起。避免"tap 卡=购买"的误触。

> 拒绝 B 的理由已在上。若未来坚持 B，也只应作为"锁态卡片常显一行锁因"的极简补充，而非完整详情常驻。

- **触屏判定**：与 mobile-adaptation-spec 一致——`@media (pointer: coarse)` 或 JS `'ontouchstart' in window` 命中即禁用 hover、启用 tap 面板。
- SVG 连线与解锁动画在触屏**照常工作**（二者非 hover 依赖：连线是常驻状态可视化，动画是状态转换），仅 hover 浮层需降级为 tap 面板。

## 2. 路径连线 · 信息语义规范

### 2.1 放置方式（DOM 路线）
每 `.st-branch-grid` 内绝对定位一个 `<svg class="st-links">` overlay（网格 `position: relative`，SVG 覆盖其完整盒尺寸）。**关键约束**：`pointer-events: none`（永不遮挡卡片点击/hover）、`z-index` 低于卡片（连线在节点下层，对齐 art-spec §2.4）。连线坐标取自各卡片中心相对网格的 offset；prereq 全分支内（v1-spec §3.1），故连线自然闭合在单网格内。购买重渲染后重新计算边状态/颜色。

> 线形：DOM 矩形卡上下文推荐**直线**（清晰、廉价）；art-spec §2.4 的二次贝塞尔为 Canvas2D 美学，DOM 下可改为极轻微曲线或直线，以可读性优先。

### 2.2 三种线语义（按"关系状态"驱动，非装饰）
| 语义类别 | 触发条件（parent → child） | 线型 | 颜色 | 不透明度 | 附加 |
|---|---|---|---|---|---|
| **已点亮路径** | owned → owned | 实线 2px | 子节点**分支色**（mid→light） | 1.0 | 分支色静态辉光 |
| **下一步引导** | owned → available（child 为 available ⇒ 其所有 prereq 必 owned，故父必 owned） | 实线 2px | 子节点分支色 | 0.85 | **流光（dash 动画）+ 强辉光**（高亮"下一步"） |
| **休眠 / 未达** | 其余（locked→*、owned→locked、available→* 等） | 虚线 `[4,4]` 2px | 灰紫 `rgb(80,80,100)` | 0.4 | 置于节点下层，无动画 |

- 分类可证完备：`available` 子节点 ⇒ 全部父 owned，其入边必为"owned→available"高亮；`owned` 子节点若父 owned ⇒ 已点亮；其余一律休眠灰虚线。恰好三态，无遗漏。

### 2.3 是否按节点类型（gate/stat/modifier/keystone）区分线型？—— **不建议（推荐否）**
**理由：**
1. **认知过载红线**：若同时承载「颜色=分支」「线型/opacity=关系状态」「线型=类型」三轴，玩家需并行解码过多视觉通道。
2. **分支色须是连线上唯一的色相通道**：让玩家一眼读出"这条路径属于哪条分支"。混入类型线型会稀释该通道。
3. **类型已由卡片三重编码**：art-spec §3.2 已用 形状+颜色+文字标签 表达类型，连线无需重复——每条边天然终止于一个"已带类型标签的卡片"。
4. **可选极小让步（延后/非必须）**：仅在子节点端点加一个**类型形状小标记**（●/■/⬡/◌，复用卡片类型词汇），不改变线本身；建议 v1 打磨**不做**，避免过载。

### 2.4 是否带「流动感」（dash 动画）？—— **仅"下一步引导"边带流光**
**理由与约束：**
- **YES（限 owned→available）**：缓动 dash（stroke-dashoffset 行进）引导视线从已点亮节点流向"下一个可买节点"，直接服务**支柱 A（明确下一站）**与 SDT 胜任感——视觉回答"我该解锁什么"。
- **NO（owned→owned）**：已完路径，静态辉光足够；全动画=噪点。
- **NO（休眠灰虚线）**：未达路径无需吸睛。
- **可访问性**：流光属装饰循环，**`prefers-reduced-motion` 下必须关闭**——但"下一步"语义须以**静态颜色/不透明度差**保留（线仍高亮、仅无流动），对齐 update-ux-spec §4。
- 新增 reduced-motion 规则**并入** style.css 既有媒体块（line 326–328 / 801–803），不新建媒体查询。

## 3. 解锁动画 · UX 语义（available → owned）

### 3.1 目标
传达"点亮 / 激活"——灵魂顺着路径注入节点、节点从可解锁态"亮起"成为永久owned。

### 3.2 时长
**推荐 420ms**（落在任务建议区间 300–500ms 内）：足够被感知为一次"点亮"，又不拖慢重渲染后的阅读流。上限不超 500ms，避免黏滞。

### 3.3 编排（脉冲 + 辉光 + 轻微缩放）
在重渲染后给被购卡加瞬时类 `.just-unlocked`（`animationend` 自动移除）：

| 相位 | 时间窗 | 动效（仅作用于边框/辉光/框） |
|---|---|---|
| 边框金光脉冲 | 0–120ms | 边框/box-shadow：基态 → 强金辉光（`#d4af37`，大扩散）→ 回落 |
| 卡片框轻缩放 | 30–300ms | 卡片**框** `scale 1.0 → 1.06（峰值~150ms）→ 1.0`，sine ease-out |
| 分支色辉光 sweep | 0–420ms | 沿边框的能量填充感（box-shadow inset / 渐变描边 由暗 → 分支色亮），收束到 owned 静态态 |
| 出边同步点亮 | 0–420ms | 该节点 → 子节点 连线 由暗 → 其状态色；若子节点变 available，则该边转入"下一步引导"流光（编排一部分） |

结束态：卡片落入 `.owned` 全分支色处理；`.just-unlocked` 移除。

### 3.4 「不干扰阅读」硬约束
1. 动画**只**作用于 卡片边界 / 边框 / box-shadow / 背景微染 + 卡片**框** transform:scale；**绝不对** 文字/描述/按钮 做 blur、fade、scale。
2. 文字层 **opacity 全程 1.0，无 filter:blur**。缩放只加在卡片 wrapper（`transform-origin: center`），或仅对 `::before/::after` 伪元素 + box-shadow 做动效，确保文字零模糊。
3. 仅用 `transform` / `opacity` 合成层（GPU），**禁用** `width/height/margin` 动画（防 reflow 抖动）。
4. **不阻塞输入**：动画非阻塞（CSS 动画，结束自动复位），`pointer-events` 保持；玩家可继续操作其他卡。
5. **单次单卡**：仅被购卡 + 其出边 动画；**不级联整树**（防认知过载 + 性能）。

### 3.5 可访问性降级（reduced-motion）
关闭全部 scale / 辉光脉冲 / dash 流光，改为**单一静态状态切换**：边框色 120ms 切到金 + 一次非动画背景微染 → 直接落入 `.owned` 态（仅 display/color 切换，对齐 update-ux-spec §4）。连线"下一步"高亮在 reduced-motion 下仍靠颜色/不透明度差表达（无流动）。

## 4. 跨三件套一致性（单一真源）

- **详情内容单真源**：桌面 hover 浮层 与 移动端 tap 面板 共用同一份"节点详情数据 + 渲染模板"，避免两套布局漂移。
- **分支色 = 唯一色相通道**：卡片描边/辉光、连线颜色、动画辉光 均取自该分支 mid/light（art-spec §2.2 五分支色板）。锁态统一去饱和灰阶（grayscale 0.85，opacity 0.55，art-spec §2.3）。
- **三态模型统一**：owned / available / locked 在 卡片 / tooltip 状态 pill / 连线语义 / 解锁动画 四处解释一致。
- **状态驱动而非装饰循环**：连线流光、available 脉冲 均由真实 prereq/owned 推导（状态驱动），非纯装饰；reduced-motion 下以颜色/opacity 差保语义。

## 5. 可访问性与降级清单（AA 级）

- **对比度**（update-ux-spec §4）：金 `#d4af37` on night ≈ 8:1；骨白 `#e8e0d0` on `#0d0a1a` ≈ 14:1，达标。tooltip 标题用金/分支 light，正文用骨白；锁因用 `#b9aed0`（保 ≥4.5:1，优于 `#a0a0b0`）以达 AA。
- **色盲友好**：节点类型三重编码（形状/图标 + 颜色 + 文字标签），不单独依赖颜色（art-spec §3.2）。连线**不以颜色承载类型**（已决定不按类型分线型），降低解码负担。
- **动效降级**：`prefers-reduced-motion` → 关闭 scale/辉光脉冲/dash 流光，改为静态颜色/opacity（update-ux-spec §4 + art-spec §3.3）。新增规则**并入** style.css 既有媒体块（line 326–328 / 801–803），不新建。
- **触控友好**：触屏命中区 ≥44px（update-ux-spec §4；移动端 `.gothic-card` 放大规则可复用）。hover 浮层不用于触屏（改 tap 面板，见 §1.4）。

## 7. 风险与红线

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | **Canvas2D vs DOM 路线分歧**：art-spec §2 描述 Canvas2D 节点，交接现状为 DOM 卡片 | 高（需确认） | 本规范按 DOM 设计；交主理人确认现状（§8 Q1）。若实为 Canvas2D，hover 改 canvas hit-test + 浮层 DOM、连线改 canvas 内绘制 |
| R2 | **过度编码 → 认知过载**：颜色+状态+类型多轴并行 | 中 | 封顶两轴（颜色=分支、线型/opacity=状态），类型交卡片承载；不按类型分线型 |
| R3 | **动画干扰阅读**：scale 含文字致模糊/抖动 | 中 | 动画只到边框/伪元素/框 transform，文字层零动效、opacity 1.0、无 blur |
| R4 | **流光过载**：全边流光成噪点 | 低 | 仅 owned→available 边流光 |

**四条设计红线核查**：本三件套纯表现层，不改数值/经济 → 不引入主导策略、无经济失衡；认知过载已由"编码轴封顶 + 移动端不常驻摘要"防范；连线/动画均服务支柱 A/C → 无支柱漂移。
